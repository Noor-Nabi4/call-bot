# Call & Flow SEO Audit

Date: 2026-10-04  
Site: https://callandflow.com/  
App: `web/` (Next.js App Router)

## Current SEO problems (before this work)

1. **Thin commercial URL footprint** — Nearly all marketing content lived on `/` with hash anchors (`/#pricing`, `/#industries`). High-intent queries like “AI receptionist” and “AI voice agents” had no dedicated landing pages.
2. **Homepage metadata misaligned** — Title/description emphasized “AI Voice Platform” rather than the primary US keyword cluster around AI voice agents / AI receptionist.
3. **Sitemap incomplete** — Only `/` and `/signup` were listed.
4. **Robots too permissive** — Authenticated ops routes (`/dashboard`, `/settings`, `/api`, etc.) were not disallowed.
5. **Weak internal linking** — Industry cards and pricing CTAs did not resolve to indexable URLs.
6. **Navigation was homepage-only** — No Product / Industries / Use Cases information architecture for crawlers or users.
7. **Schema scope issues** — Homepage WebPage/HowTo/ItemList JSON-LD was injected sitewide from the root layout.
8. **No blog/resources foundation** — No durable content system for supporting articles.
9. **Duplicate pricing destination** — Marketing referenced `/#pricing` while a full pricing story belonged on `/pricing`.
10. **No reusable page metadata helper** — Risk of copying homepage OG tags onto new pages.

## Changes made

### Metadata & technical

- Updated default title/description/keywords in `src/lib/seo.ts`
- Added `buildPageMetadata()` for unique title, description, canonical, Open Graph, Twitter
- Split sitewide JSON-LD (`Organization`, `WebSite`, `SoftwareApplication`) from homepage-only schemas
- Added reusable FAQ, Breadcrumb, WebPage, and Product offer JSON-LD helpers
- Expanded `sitemap.ts` to include product, industry, use-case, pricing, blog, and signup URLs
- Updated `robots.ts` to disallow authenticated/internal routes and keep sitemap/host
- Added metadata unit tests

### Homepage

- H1 → “AI Voice Agents for Your Business”
- Metadata aligned to primary keyword + conversion copy
- Internal links to `/ai-voice-agents`, `/ai-receptionist`, `/industries`, `/pricing`
- Industry cards link to dedicated industry URLs
- Pricing compare CTA points to `/pricing`
- How-it-works section restored on homepage for crawlable process content
- FAQ updated to real search questions with FAQPage schema

## Metadata strategy

- Root layout provides defaults + `metadataBase`
- Every indexable marketing page calls `buildPageMetadata({ title, description, path, keywords? })`
- Canonicals use path-relative values resolved via `metadataBase` / `NEXT_PUBLIC_SITE_URL`
- Open Graph / Twitter reuse `/opengraph-image` and `/twitter-image`
- Login and ops surfaces remain `noindex` (login layout already set)

## URL structure

Clean, keyword-relevant paths:

- `/ai-receptionist`
- `/ai-voice-agents`
- `/industries/{slug}`
- `/use-cases/{slug}`
- `/pricing`
- `/blog/{slug}`

No query-parameter landing pages for SEO content.

## Sitemap

Generated by `src/app/sitemap.ts` from:

- `PUBLIC_MARKETING_ROUTES`
- `industryPages`
- `useCasePages`
- `blogPosts`

Excludes dashboard, settings, API, playground, and other private routes.

## Robots

`src/app/robots.ts` allows public marketing pages and disallows authenticated/internal prefixes listed in `ROBOTS_DISALLOW`.

## Schema

| Schema | Where |
|---|---|
| Organization / WebSite / SoftwareApplication | Root layout (sitewide) |
| WebPage + HowTo + ItemList | Homepage |
| FAQPage | Homepage, product, industry, use-case, pricing pages with visible FAQs |
| BreadcrumbList | Inner marketing pages |
| Product + Offer | Pricing (from live catalog when available) |
| Article | Blog posts |

No fake ratings/reviews AggregateRating markup.

## Internal linking

- Homepage → product, industries hub, pricing
- Industry pages → related industries, use cases, AI receptionist, AI voice agents, pricing
- Use-case pages → related industries/use cases + commercial pages
- Blog posts → commercial CTAs
- Nav/footer reinforce the same graph with varied anchor text

## Performance notes

- Reused existing landing primitives (`Reveal`, `PageHero`, `Faq`, etc.) instead of new heavy client islands where possible
- Marketing content modules are server-rendered data (no client fetch for SEO copy)
- Pricing page still fetches live catalog from platform API (`no-store`) — expected for accurate plan data
- Brand logo SVG remains `<img>` for lockups (existing pattern)
- Did not strip brand animations; reveal animations respect `prefers-reduced-motion`

## Remaining recommendations

1. Set production `NEXT_PUBLIC_SITE_URL=https://callandflow.com` in the deployed environment (do not ship staging hostnames as canonical).
2. Submit sitemap in Google Search Console and monitor coverage for new URLs.
3. Add unique OG images per major template later if social CTR matters.
4. Expand blog with 1–2 high-quality articles per month (see `SEO-ROADMAP.md`) — avoid thin posts.
5. Add HTML sitemap page only if crawl discovery remains weak after indexation.
6. Consider `hreflang` only if launching non-US locales.
7. Validate FAQ rich results in Rich Results Test after deploy.
8. Wire analytics/`dataLayer` events for new CTA sources if not already captured via `nav_click`.
9. Ensure trailing-slash and www preferences are enforced at the reverse proxy / CDN to match canonical host.
10. When CRM/calendar integrations ship, update product copy and schema `featureList` from real capabilities only.
